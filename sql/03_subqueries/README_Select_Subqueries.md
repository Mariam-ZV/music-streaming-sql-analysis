# SQL Subqueries — SELECT Clause Analysis

This section of the project focuses on using SQL subqueries inside the `SELECT` clause to add analytical context to query results within a music streaming dataset.

The analysis introduces KPI-style calculations and comparative metrics by combining row-level or group-level results with platform-wide benchmarks.

## Skills Demonstrated

- Subqueries in `SELECT` clauses
- KPI-style analytical calculations
- Benchmark comparisons
- Percentage contribution analysis
- Aggregate functions with contextual metrics
- Multi-table joins with grouped analysis
- Platform-wide performance comparisons
- Business-oriented metric calculation

## Key Business Questions Explored

### Artist Contribution Analysis
- For each artist, calculate total streams and percentage contribution to overall platform streams.

### Track Benchmarking
- Compare each track’s performance against the global average stream count.
- Measure the difference between individual streaming records and the platform average.

### Label Performance Context
- Show label-level total streams alongside overall platform stream totals.

### Genre Contribution Analysis
- Calculate total streams generated by each genre.
- Measure each genre’s share of total platform streams.

## Analytical Highlights

A major focus of this section was learning how to combine local performance metrics with larger platform benchmarks inside a single query result.

Examples include:
- Comparing individual track performance against platform averages
- Measuring percentage contribution to total platform streams
- Displaying group-level KPIs alongside global metrics
- Creating contextual analytical outputs directly within query results

The analysis also introduced the concept of:
- row/group metrics vs global metrics
- contextual calculations
- analytical reporting within SQL queries

## Example Concepts Practiced

### Percentage Contribution
Calculating what percentage of total platform streams each artist or genre contributes.

### Benchmark Comparison
Comparing track-level performance against the global average stream count.

### KPI Contextualisation
Displaying overall platform metrics alongside artist, label, or genre performance to create more meaningful analytical outputs.

## Dataset Structure Used

The queries were built using a relational music streaming schema containing:

- `artists`
- `genres`
- `labels`
- `releases`
- `tracks`
- `streaming_stats`
- `track_genres`

The project involved both one-to-many and many-to-many relationships, including use of the `track_genres` bridge table.

## Key Takeaway

This phase improved my understanding of contextual analytics within SQL. Using subqueries inside the `SELECT` clause helped strengthen my ability to create business-focused metrics and comparative reporting directly within SQL query outputs.
